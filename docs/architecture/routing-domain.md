# Доменный слой маршрутизации

Дата перехода: 20.08.2026.

## Результат пункта 2

Медицинские правила, справочники территорий, принимающие организации и расчёт конечного маршрута перенесены из React-компонентов в `src/routing`. Интерфейс отвечает только за ввод данных и отображение результата.

Текущее поведение не изменялось: перенос выполнен под контролем регрессионных тестов, созданных на пункте 1.

## Структура

| Файл | Ответственность |
| --- | --- |
| `types.ts` | общий идентификатор и контракт профиля |
| `registry.ts` | единый реестр всех профилей и порядок карточек на главном экране |
| `obstetrics.ts` | акушерство и гинекология |
| `bsk.ts` | БСК / ССЗ |
| `oncology.ts` | онкология |
| `dermatology.ts` | дерматовенерология |
| `infectious.ts` | инфекционные болезни взрослых |
| `road-accident.ts` | ДТП и травма |

Каждый профиль предоставляет метаданные и чистую расчётную функцию через `RoutingProfileDefinition<State, Result>`.

## Защита границы

- Модулям `src/routing` запрещено импортировать React и вышележащие UI-компоненты правилом ESLint.
- Модульные тесты импортируют правила непосредственно из доменного слоя.
- Главный экран получает карточки из `routingProfileList`, поэтому новый профиль нельзя добавить только в навигацию, забыв зарегистрировать его как расчётный модуль.
- `App.tsx` содержит исчерпывающее сопоставление идентификатора профиля и React-компонента, проверяемое TypeScript.

## Переход к пункту 3

Введена схема `RoutingProfileContentDocument`: все профили получили версию содержимого, статус публикации, формальные списки вопросов и веток, официальные источники и блокирующие вопросы к кураторам. Подробности приведены в `docs/architecture/versioned-routing-content.md`.

Интерпретатор `rules_v1` реализован; все шесть профилей переведены на него после параллельной проверки против прежних функций. Доменный слой готов к подключению административного редактора версий, каталогов и исполняемых правил.

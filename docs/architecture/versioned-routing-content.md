# Версионируемое содержимое маршрутизации

Дата введения схемы: 20.08.2026.

## Назначение

Схема отделяет редакцию медицинского содержимого от версии приложения. Изменение вопроса, приоритета ветки, принимающей организации или нормативного основания должно создавать новую редакцию профиля, а не молча изменять опубликованный маршрут.

Текущая версия схемы — `1`. Все шесть профилей заведены как `0.3.0-draft.1` и имеют статус `draft`.

## Состав документа

Каждый `RoutingProfileContentDocument` содержит:

- идентификатор профиля, версию схемы и SemVer-версию содержимого;
- статус и дату редакции;
- формальный список вопросов опросника;
- упорядоченный список конечных веток с условиями и результатами;
- ссылки веток на официальные федеральные или региональные источники;
- блокирующие вопросы к кураторам;
- механизм выполнения правил;
- реквизиты согласования для утверждённой версии.

Сейчас формально описаны 42 конечные ветки. Документы являются обычными JSON-совместимыми объектами: они проходят runtime-проверку, сериализуются и могут позднее храниться в базе данных без функций React.

## Статусы

| Статус | Значение |
| --- | --- |
| `draft` | рабочая редакция администрации |
| `in_review` | редакция передана куратору на проверку |
| `approved` | редакция согласована и может быть опубликована |
| `archived` | ранее утверждённая редакция выведена из действия, но сохранена для аудита |

Разрешённый рабочий переход: `draft` → `in_review` → `approved` → `archived`. Для изменения действующей версии создаётся новый черновик с новым `contentVersion`.

## Защита публикации

Версия не может получить статус `approved`, если:

- остался хотя бы один блокирующий вопрос к куратору;
- источник имеет статус `needs_confirmation` или `season_expired`;
- отсутствуют ФИО согласовавшего, дата и реквизиты решения;
- нарушена структура документа, повторяются идентификаторы или приоритеты;
- ветка ссылается на неизвестный источник или вопрос.

Для проекта на уровне схемы закреплено требование `officialSourcesOnly: true`. Неофициальный источник не проходит проверку.

## Текущее ограничение исполнения

Для всех шести профилей `execution.kind` равен `rules_v1`: маршруты рассчитываются безопасным интерпретатором из JSON-совместимых правил. Прежние TypeScript-функции не используются основным интерфейсом и сохранены для параллельного регрессионного контроля до окончания опытной эксплуатации административного редактора.

Первый обзорный экран административного интерфейса реализован поверх версионируемых документов и наборов `rules_v1`. Следующий шаг — подключить постоянное серверное хранилище и редактирование через отдельный черновик, не меняющий действующую версию напрямую. Подробности движка и выполненного сопоставления приведены в `docs/architecture/rules-v1.md`, модель доступа — в `docs/architecture/admin-access.md`.

## Связанные файлы

- `src/routing/content-schema.ts` — контракт, проверка и переходы статусов;
- `src/routing/content-manifests.ts` — шесть текущих версионируемых документов;
- `tests/unit/routing-content-schema.test.ts` — проверка структуры, сериализации, реестра вопросов и запрета преждевременной публикации.

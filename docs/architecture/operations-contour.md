# Операционный контур

## Назначение

Операционный контур закрывает три задачи, которые не относятся к медицинскому вычислению маршрута:

1. хранение и публикация метаданных нормативных документов;
2. приём обратной связи от врачей и работа администратора с обращениями;
3. обезличенный учёт использования для испытаний и эксплуатации.

Все эти функции отделены от версионируемого дерева маршрутизации. Изменение карточки приказа или статуса обращения не меняет действующий маршрут.

## Хранение

Neon Postgres хранит:

- `normative_documents` — карточки приказов и реквизиты сохранённых копий;
- `normative_document_references` — связи документа с профилем, веткой и идентификатором источника;
- `normative_document_relations` — связи «изменяет», «заменяет», «дополняет»;
- `routing_feedback` — обращения без обязательных персональных реквизитов;
- `feedback_recipients` — адресаты уведомлений;
- `usage_daily_stats` — дневные счётчики событий;
- `operations_admin_audit_log` — аудит действий единственной учётной записи `admin`.

Сохранённые копии PDF/DOCX размещаются в Vercel Blob. В Neon остаются URL, исходное имя, MIME-тип, размер и SHA-256. Git не используется как хранилище приказов.

## Привязка приказа к маршруту

Стабильная метка документа (`code`) идентифицирует карточку независимо от имени файла. Одна карточка может иметь несколько привязок:

- только профиль — документ показывается для всего профиля;
- профиль + ветка — уточняет область применения;
- профиль + `sourceId` — связывает карточку с нормативным источником, указанным в версии маршрута;
- профиль + ветка + `sourceId` — максимально точная связь.

В публичной части показываются неархивные документы, связанные с открытым профилем. Статусы `needs_confirmation`, `expired` и `replaced` визуально отличаются от `active`.

Предоставленная пользователем копия подтверждает наличие материала для разбора, но не доказывает его текущий юридический статус. Поэтому начальные карточки без официальной ссылки и отметки сверки имеют статус `needs_confirmation`. Для региональных приказов приоритетны страницы на домене органов власти Новгородской области `novreg.ru`; для федеральных документов — официальные ресурсы Минздрава России и портала опубликования правовых актов.

## Обратная связь

Публичная форма автоматически прикладывает только технический контекст: профиль, версию, результат и идентификатор правила. Врач получает явное предупреждение не указывать сведения о пациенте.

Сначала обращение сохраняется в Neon. Отправка письма является вторичной операцией: её сбой не приводит к потере обращения. Если настроены `RESEND_API_KEY`, `FEEDBACK_FROM_EMAIL` и хотя бы один включённый адресат, письмо содержит номер обращения и ссылку в админку, но не полный текст сообщения.

## Статистика и приватность

События агрегируются в день записи. Хранятся только:

- дата;
- профиль;
- версия маршрута;
- вид события;
- короткое техническое измерение (например, идентификатор правила);
- количество.

Не сохраняются ответы опросника, ФИО, телефон, адрес пациента, IP-адрес и идентификатор устройства. Статистика предназначена для оценки использования и завершения маршрутов, а не для медицинского наблюдения.

## Переменные окружения

Обязательные для основного контура:

- `DATABASE_URL`;
- `ADMIN_PASSWORD`;
- `ADMIN_SESSION_SECRET`.

Необязательные:

- `BLOB_READ_WRITE_TOKEN` — загрузка сохранённых копий документов;
- `RESEND_API_KEY` и `FEEDBACK_FROM_EMAIL` — уведомления по электронной почте;
- `PUBLIC_SITE_URL` — абсолютная ссылка на административный раздел в письме.

## Ввод в эксплуатацию

1. Применить `npm run db:migrate`.
2. Проверить `npm run db:check`.
3. В Vercel добавить обязательные переменные для Production и Preview.
4. При необходимости подключить Blob и Resend.
5. Выполнить production deployment.
6. Пройти программу испытаний из `docs/testing/acceptance-test-program.md` и заполнить протокол.

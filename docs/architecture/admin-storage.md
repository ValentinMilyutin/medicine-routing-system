# Хранилище административных версий

Дата подключения: 20.08.2026.

## Результат

К проекту Vercel `medicine-routing-system` подключён ресурс Neon Postgres `medicine-routing-db` на бесплатном тарифе в регионе Frankfurt. Интеграция предоставляет `DATABASE_URL` для Production, Preview и Development. Значение строки подключения хранится только в переменных окружения и не добавляется в Git.

База содержит исключительно содержимое маршрутизации. Ответы пользователей, сведения о пациентах и результаты прохождения опросников не записываются.

## Таблицы

- `routing_content_versions` — текущее состояние каждой версии профиля, статус и номер ревизии;
- `routing_content_revisions` — неизменяемый снимок документа и `rules_v1` после каждого сохранения;
- `routing_admin_audit_log` — действие, время и фиксированный исполнитель `admin`.

Для одного профиля и номера версии действует уникальность. Одновременно может существовать не более одной версии профиля со статусом `approved`. Изменение черновика использует ожидаемый номер ревизии: если одна вкладка уже сохранила новую ревизию, устаревшая вкладка не сможет молча перезаписать её.

Черновик хранит единственную связь происхождения: `based_on_version_id` и
`based_on_content_version`. Попарные связи и сравнения между черновиками не
создаются. В административном интерфейсе каждый кандидат сравнивается только с
текущей рабочей версией профиля.

## Серверный API

`/api/admin/content` доступен только при действующей подписанной admin-сессии:

- `GET` — список сохранённых версий;
- `GET ?id=` — документ и исполняемые правила выбранной версии;
- `GET ?effectiveProfileId=` — единственная текущая рабочая версия: утверждённая
  из Neon либо встроенная резервная до первой публикации;
- `POST action=create_draft` — новая независимая версия на основе последнего сохранённого либо встроенного профиля;
- `POST action=save_draft` — новая ревизия существующего черновика.
- `POST action=submit_review` — передача сохранённого кандидата на проверку;
- `POST action=approve` — публикация кандидата с автоматическим архивированием
  прежней утверждённой версии;
- `POST action=archive` — вывод утверждённой версии из действия.

Любой документ и набор правил повторно проходят серверную runtime-проверку. Изменяющие запросы с чужого origin отклоняются. Ответы не кэшируются.

## Эксплуатация

```bash
npm run db:migrate
npm run db:check
```

Миграция идемпотентна. `db:check` выполняет только чтение и подтверждает наличие трёх таблиц и количество записей. Локальные значения берутся из игнорируемого `.env.local`.

Административный экран отдельно показывает текущую рабочую версию и кандидатов.
Для каждого кандидата рассчитывается смысловая сводка отличий от текущей версии:
вопросы, логика и результаты маршрутов, источники и пояснения. Для инфекционного
профиля подключён визуальный конструктор полного сценария и интерактивный
предпросмотр выбранной версии.

Публичный инфекционный опросник использует утверждённую версию из Neon. Пока её
нет, действует встроенная резервная версия; сохранение черновика её не меняет.

Перед сохранением инфекционного черновика и клиент, и сервер проверяют структуру
правил, ссылки на поля и варианты ответов, обязательную клиническую матрицу и
автоматически сформированные сочетания динамического опросника. Старые черновики,
созданные до введения формальных вариантов ответа, безопасно нормализуются при
чтении и сохраняют прежнюю исполняемую логику. Следующий этап — опытная
эксплуатация пилота и перенос конструктора на остальные профили.

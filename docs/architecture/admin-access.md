# Доступ к административному контуру

Дата фиксации модели: 20.08.2026.

## Модель доступа

В текущих требованиях есть ровно два режима:

1. Публичный пользователь без учётной записи. Он выбирает профиль, отвечает на вопросы и получает справочную информацию о маршрутизации.
2. Единственная учётная запись `admin` с полными административными правами. Роли, регистрация, кабинеты врачей и дополнительные администраторы не предусмотрены до появления отдельного требования.

Публичные опросники не должны зависеть от состояния административной сессии. Наличие закрытого контура не превращает основной сайт в систему с обязательной авторизацией.

## Реализованная граница безопасности

- пароль хранится только в серверной переменной `ADMIN_PASSWORD`;
- ключ подписи сессии хранится только в `ADMIN_SESSION_SECRET` и должен содержать не менее 32 символов;
- имя `admin` фиксировано на сервере и не вводится пользователем;
- успешный вход создаёт подписанную cookie на 8 часов с атрибутами `HttpOnly` и `SameSite=Strict` (`Secure` на HTTPS);
- персонализированные ответы API не кэшируются;
- изменяющие запросы принимаются только с origin самого сайта;
- клиентский код не содержит пароль или ключ подписи и не получает их от сервера.

В Vercel обе переменные следует создать для нужных окружений проекта. После изменения переменных нужен новый deployment. Для локальной проверки полного контура используется среда, которая запускает и Vite, и Vercel Function; обычный `npm run dev` обслуживает только клиентский интерфейс.

## Этапы административного контура

Администратор видит профили, версии, статусы, количество вопросов и клинических исходов, официальные источники и блокирующие вопросы. Редактирование выполняется только через отдельный черновик версии; действующая маршрутизация не изменяется напрямую.

Для инфекционного профиля реализован пилотный визуальный конструктор вопросов, вариантов ответов, условий показа, исполняемых веток и результатов. Есть ручное тестовое прохождение и автоматическая матрица сочетаний с поиском пробелов, недостижимых и перекрытых веток. Перед сохранением сервер повторно проверяет административную сессию, целостность опросника и правил, а также обязательные клинические сценарии. Публикация остаётся отдельным следующим этапом и должна дополнительно проверять официальность источников, блокирующие вопросы и реквизиты согласования.

Постоянное серверное хранилище подключено через Neon Postgres. Структура версий, ревизий и аудита описана в `admin-storage.md`; сохранение только в браузере не используется.

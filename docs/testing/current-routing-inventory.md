# Инвентаризация текущей маршрутизации

Дата фиксации: 20.08.2026.

## Назначение

Этот документ фиксирует медицинскую логику, которая на пункте 2 перенесена из React-компонентов в доменные модули `src/routing`. Автоматические тесты являются исполняемой спецификацией: если изменится больница, приоритет или предупреждение, тест покажет конкретное расхождение.

Пункт 1 считается выполненным для текущего состава профилей: все известные категории конечных маршрутов представлены тестами, пограничные приоритеты зафиксированы, неполные формы проверены, а неподтверждённые решения вынесены в отдельный реестр.

## Проверенные обязательные поля

- Профиль не должен выдавать маршрут до выбора минимально необходимого контекста.
- Дерматовенерология требует территорию, состояние и, при отсутствии четырёх опасных состояний, решение о стационарном лечении.
- Инфекционный профиль требует территорию, группу инфекции, ответ по жизнеугрозам и критерий стационара; тяжёлое общее течение дополнительно требует транспортабельность.
- ДТП требует тип места, возраст, критерий травмы и соответствующую территорию или зону трассы.
- БСК требует распознаваемую территорию.
- Акушерский профиль требует сценарий; обычные территориальные ветки требуют территорию и профильные параметры.
- В онкологии обязательность территории и статуса обеспечивается пользовательским интерфейсом; сама расчётная функция сохраняет технический резервный результат для неизвестной территории.

## Зафиксированные приоритеты

### Акушерство

Текущее правило: инфекция → травма → хирургия → тяжёлая экстрагенитальная патология → критическое акушерское состояние → обычная ветка. Этот порядок покрыт отдельными конфликтными тестами и требует клинического подтверждения перед промышленным применением.

### БСК

Нарушение витальных функций перекрывает ОНМК, ОКС, другие ССЗ и КИНК: сначала показывается ближайшая доступная ОАРИТ.

### Онкология

Текущее правило: подозрение на инфаркт/ОНМК → хирургический/инвазивный синдром → общая неотложность → паллиативный маршрут → обычная медицинская перевозка → плановый или негоспитальный результат.

### Инфекции

Жизнеугроза перекрывает критерии стационарного и амбулаторного лечения. В интерфейсе варианты «нет угроз» и «нет показаний» взаимоисключающие; тесты дополнительно фиксируют поведение расчётной функции при противоречивом наборе данных.

## Автоматические проверки

- `npm run test` — 190 модульных, архитектурных и UI-проверок.
- `npm run test:e2e` — сквозные сценарии в установленном Chrome для desktop и mobile.
- `npm run lint` — статический анализ.
- `npm run build` — проверка TypeScript и production-сборки.
- `npm run test:all` — полный последовательный контроль.

Тестовые файлы находятся в `tests/unit`, `tests/ui` и `tests/e2e`.

## Выявленная техническая ошибка

Реальный браузерный тест обнаружил падение дерматовенерологического профиля после выбора территории: обработчик читал `event.currentTarget.value` внутри отложенного обновления состояния. Значение теперь сохраняется до вызова обновления. Медицинская логика маршрута не менялась.

## Состояние после пункта 2

Расчётные функции и связанные справочники находятся в `src/routing`, а React-компоненты отвечают за ввод и отображение. Подробная схема приведена в `docs/architecture/routing-domain.md`.

Тесты фиксируют текущее поведение, но не подтверждают медицинскую правильность спорных решений. Спорные правила нельзя молча «улучшать»: изменение допускается только после ответа куратора и одновременного обновления тестового ожидания с указанием основания.

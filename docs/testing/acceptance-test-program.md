# Программа и методика приёмочных испытаний

## 1. Объект испытаний

Веб-приложение «Маршрутизация СМП» для выбора места транспортировки пациента по территории и клиническим критериям, а также административный контур управления версиями маршрутов, нормативными документами и обратной связью.

Документ задаёт воспроизводимую проверку MVP. Он не подтверждает медицинскую корректность непроверенных кураторами правил: такая проверка проводится отдельно по реестру открытых вопросов.

## 2. Цель

Подтвердить, что:

- публичная часть доступна без авторизации;
- каждый поддерживаемый профиль доводит полный допустимый набор ответов до однозначного результата;
- выход маршрута содержит место назначения либо явно обозначенное обязательное согласование, если конкретное учреждение отсутствует в нормативном источнике;
- администратор может создать, изменить, проверить, сравнить и опубликовать версию логики;
- неопубликованный черновик не меняет публичный маршрут;
- документы, обращения и статистика работают независимо от медицинской логики;
- персональные данные пациента не запрашиваются и не входят в эксплуатационную статистику.

## 3. Условия

- актуальная версия в ветке `main`;
- тестовое и production-окружения Vercel;
- применённые миграции Neon;
- браузеры Chromium desktop и мобильный viewport;
- тестовая учётная запись `admin`;
- для проверки загрузки — подключённый Vercel Blob;
- для проверки писем — тестовый адресат и настроенный Resend.

## 4. Автоматические проверки

Перед ручной приёмкой выполнить:

```bash
npm ci
npm run lint
npm run test
npm run build
npm run test:e2e
npm run db:check
```

Критерий: каждая команда завершается с кодом 0. Предупреждение об устаревших данных Browserslist не считается отказом, если сборка завершилась успешно.

## 5. Ручные сценарии

### ПИ-01. Публичный доступ

1. Открыть сайт в приватном окне.
2. Убедиться, что видны шесть профилей.
3. Открыть любой профиль без входа.

Ожидается: авторизация не запрашивается; административные функции недоступны.

### ПИ-02. Полный маршрут каждого профиля

Для акушерства/гинекологии, онкологии, БСК/ССЗ, дерматовенерологии, инфекционных болезней взрослых и ДТП/травмы:

1. выбрать территорию;
2. заполнить обязательные клинические критерии;
3. получить итог;
4. сверить наименование и адрес с утверждённым контрольным примером;
5. изменить ключевой ответ и проверить изменение ветки.

Ожидается: результат не появляется при незаполненных обязательных вопросах; после заполнения выбран ровно один приоритетный маршрут; место назначения и пояснения соответствуют контрольному примеру.

### ПИ-03. Управление логикой

1. Войти как `admin`.
2. Создать черновик на основе действующей версии.
3. Добавить вопрос каждого используемого типа.
4. Для числового вопроса задать единицу измерения, допустимый диапазон и условие сравнения.
5. Добавить правило с условием, приоритетом и результатом, содержащим медицинскую организацию и адрес.
6. Добавить положительный и граничный контрольные примеры.
7. Запустить автоматическую проверку логики и сравнение с действующей версией.

Ожидается: недостижимые ветки, неоднозначные совпадения, неверные ссылки и незаполненные результаты блокируют публикацию; валидная версия показывает поведенческие отличия.

### ПИ-04. Публикация и возврат

1. Убедиться, что сохранённый черновик не изменил публичную часть.
2. Перевести валидный черновик на проверку и утвердить.
3. Обновить публичный профиль и проверить номер версии и новый результат.
4. Создать новый черновик на основе предыдущей рабочей версии либо опубликовать сохранённую проверенную версию.

Ожидается: одновременно действует одна опубликованная версия; остальные версии хранятся отдельно; переключение фиксируется в аудите.

### ПИ-05. Реестр документов

1. Открыть вкладку «Документы».
2. Создать карточку с уникальной меткой, номером, датой, издателем и статусом.
3. Привязать карточку к профилю, затем к конкретной ветке/источнику.
4. Загрузить PDF или DOCX размером до 25 МБ.
5. Открыть публичный профиль и сохранённую копию.
6. Перевести документ в архив.

Ожидается: реквизиты и SHA-256 сохранены; документ виден только в связанных профилях; архивная запись не показывается публично; файл другого формата или больше 25 МБ отклоняется.

### ПИ-06. Обратная связь

1. На публичной странице отправить обращение без данных пациента.
2. Открыть вкладку «Обратная связь».
3. Найти обращение по номеру, проверить автоматически приложенный контекст.
4. Изменить статус и добавить внутренний комментарий.
5. При настроенной почте проверить получение уведомления.

Ожидается: обращение сохраняется даже при недоступной почтовой интеграции; полный текст виден в админке; письмо не содержит текст обращения.

### ПИ-07. Обезличенная статистика

1. Открыть профиль, завершить маршрут, открыть документ и отправить обращение.
2. Открыть вкладку «Статистика».
3. Проверить счётчики за текущую дату.
4. Проверить структуру `usage_daily_stats`.

Ожидается: счётчики увеличены; в таблице отсутствуют ответы опросника, сведения о пациенте, IP и идентификатор устройства.

### ПИ-08. Адаптивность и отказоустойчивость

1. Повторить критический маршрут на ширине 375 px.
2. Временно проверить поведение при недоступном API опубликованной версии.
3. Проверить форму обращения при недоступной почте.

Ожидается: элементы доступны без горизонтальной потери управления; используется встроенная резервная версия; сохранённое обращение не теряется из-за сбоя уведомления.

## 6. Критерии завершения

Испытания считаются пройденными, если:

- все автоматические проверки успешны;
- нет дефектов, способных выдать неверное или неоднозначное место назначения;
- нет обхода административной авторизации;
- все замечания высокой критичности устранены;
- медицинские открытые вопросы либо подтверждены куратором, либо явно обозначены и блокируют публикацию соответствующей логики;
- заполнен протокол испытаний.
